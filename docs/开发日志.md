## 2026-08-14：阶段 0 - 基线梳理与项目重新定位

### 本次目标

将项目从“校园二手交易平台”调整为“可信交易与资金风控平台”的发展方向，同时保持现有工程名称、包名、数据库名、表结构与 API 路径兼容，为后续订单状态机、模拟支付、账务流水和风控能力建设准备基础设施。

### 已完成

- 更新 README、产品 PRD、开发基准中的项目定位：面向个人、组织与园区的可信闲置资产交易场景。
- 更新用户端和管理端的可见文案：将“校园、学号、同学”泛化为“平台、账号、用户、平台交易地点”。
- 保留 `campus-trade-*` 工程目录、`com.campus.trade` 包名、`campus_trade` 数据库名、`username` 字段和 `meetup_location` 表，避免对现有环境和接口造成破坏性变更。
- 新增 API 响应字段 `errorCode` 与 `traceId`，同时保留已有 `code`、`msg`、`data` 响应字段。
- 新增请求追踪：服务端生成或透传 `X-Trace-Id`，响应头、响应体与服务端日志可使用该标识关联请求。
- 调整请求日志：记录请求方法、路径、状态码和耗时；不再输出登录接口的请求头和请求体，避免密码或认证令牌泄漏。
- 为登录、注册、创建订单接口增加服务端参数校验，并统一返回 `VALIDATION_ERROR`。

## 2026-08-14：阶段 1 - 订单状态机与库存一致性

### 已完成

- 建立订单状态机：面交订单由买家从待交易确认完成；快递订单由卖家从待发货发货，再由买家确认完成；买家只能在履约开始前取消。
- 商品状态调整为 `AVAILABLE -> LOCKED -> SOLD/AVAILABLE`；下单通过条件更新原子锁定商品，同一商品被并发下单时仅一个请求能创建订单。
- 取消、完成和管理员强制取消均使用“当前状态 -> 目标状态”的条件更新，并同步校验商品状态，避免重复操作、状态回退和商品错误释放。
- 新增意图型订单接口：取消、确认完成、卖家发货、管理员强制取消；移除普通用户通用状态更新和管理员创建、编辑、删除订单、代替卖家发货的接口入口。
- 用户端新增买家确认完成与卖家发货操作；管理端订单页仅保留查询和未履约订单的强制取消，配送页调整为只读监控。
- 商品锁定或售出后禁止编辑、手动上下架和再次下单。

### 验证结果

- 后端 `mvn test` 通过：共 6 个测试，其中新增订单服务单元测试覆盖商品已锁定时不创建订单、取消释放商品、买家确认完成与卖家发货权限校验。
- 用户端与管理端 `npm.cmd run build` 均通过。
- 旧的订单通用状态更新、管理员自由编辑/删除/创建订单、管理员代替卖家发货调用均已从订单链路中清除。
- `git diff --check` 通过。
