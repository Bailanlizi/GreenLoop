## 2026-08-14：阶段 0 - 基线梳理与项目重新定位

### 本次目标

将项目从“校园二手交易平台”调整为“可信交易与资金风控平台”的发展方向，同时保持现有工程名称、包名、数据库名、表结构与 API 路径兼容，为后续订单状态机、模拟支付、账务流水和风控能力建设准备基础设施。

### 已完成

- 更新 README、产品 PRD、开发基准中的项目定位：面向个人、组织与园区的可信闲置资产交易场景。
- 更新用户端和管理端的可见文案：将“校园、学号、同学”泛化为“平台、账号、用户、平台交易地点”。
- 保留 `campus-trade-*` 工程目录、`com.campus.trade` 包名、`campus_trade` 数据库名、`username` 字段和 `meetup_location` 表，避免对现有环境和接口造成破坏性变更。

- 新增请求追踪：服务端生成或透传 `X-Trace-Id`，响应头、响应体与服务端日志可使用该标识关联请求。

## 2026-08-14：阶段 1 - 订单状态机与库存一致性

### 已完成

- 建立订单状态机：面交订单由买家从待交易确认完成；快递订单由卖家从待发货发货，再由买家确认完成；买家只能在履约开始前取消。
- 商品状态调整为 `AVAILABLE -> LOCKED -> SOLD/AVAILABLE`；下单通过条件更新原子锁定商品，同一商品被并发下单时仅一个请求能创建订单。
- 取消、完成和管理员强制取消均使用“当前状态 -> 目标状态”的条件更新，并同步校验商品状态，避免重复操作、状态回退和商品错误释放。
- 新增意图型订单接口：取消、确认完成、卖家发货、管理员强制取消；移除普通用户通用状态更新和管理员创建、编辑、删除订单、代替卖家发货的接口入口。
- 用户端新增买家确认完成与卖家发货操作；管理端订单页仅保留查询和未履约订单的强制取消，配送页调整为只读监控。
- 商品锁定或售出后禁止编辑、手动上下架和再次下单。

### 验证结果

- 后端 `mvn test` 通过：共 6 个测试，其中新增订单服务单元测试覆盖商品已锁定时不创建订单、取消释放商品、买家确认完成与卖家发货权限校验。
- 用户端与管理端 `npm.cmd run build` 均通过。
- 旧的订单通用状态更新、管理员自由编辑/删除/创建订单、管理员代替卖家发货调用均已从订单链路中清除。
- `git diff --check` 通过。

## 2026-08-15：阶段 2 - 模拟账户、支付与资金流水

### 已完成

- 新增单币种模拟账户，维护可用余额、冻结余额、账户状态和乐观锁版本；新用户注册时开户，存量用户通过迁移脚本回填，并保留惰性开户兜底。
- 新增充值单、支付单、冻结记录、退款单、结算单和不可变资金流水；所有金额统一使用 `DECIMAL(18,2)` 与 `BigDecimal`，资金更新同时校验版本、账户状态和非负余额。
- 下单状态调整为 `PENDING_PAYMENT`，商品保持 `LOCKED`；买家支付后资金由可用余额转入冻结余额，订单才进入待面交或待发货状态。
- 买家或管理员取消已支付且未履约订单时，自动解冻并全额退回买家可用余额；确认完成时扣减买家冻结余额并增加卖家可用余额。
- 充值和支付使用调用方 `requestId` 与数据库唯一约束实现幂等；支付、退款和结算以订单号建立唯一约束，配合订单行锁和条件更新防止重复入账。
- 新增 30 分钟待支付超时任务，按候选订单逐笔加锁、独立事务关闭订单并释放商品，避免与同时发生的支付请求冲突。
- 用户端新增资金账户、模拟充值、充值记录和资金流水页面；购买订单新增支付入口和支付倒计时。
- 管理端新增只读资金管理页面，可分页查询账户、支付、退款、结算和资金流水，不提供人工调账或流水删除能力。
- 保留阶段一历史订单兼容：迁移前创建且没有支付截止时间的存量订单可以继续取消或完成，不伪造资金记录；阶段二新订单严格要求有效支付记录。
- 更新完整初始化脚本，并新增 `scripts/stage2_finance_migration.sql` 非破坏性升级脚本。现有环境应先选择目标数据库，再执行迁移脚本。

### 验证结果

- 后端 `mvn test` 通过：共 15 个测试，覆盖待支付订单、充值幂等、余额不足、支付冻结、请求号复用、取消退款、完成结算和超时释放。
- 用户端与管理端 `npm.cmd run build` 均通过；仅保留既有的大体积 chunk 警告。
- 非破坏性迁移已在 `campus_trade_test` 执行成功：7 张资金表和支付截止字段完整，4 个存量用户全部开户，订单金额精度升级为 `DECIMAL(18,2)`。
- 完整初始化脚本已在临时空库验证，可成功创建 21 张业务表；验证库已清理。
- 真实 HTTP 冒烟验证通过：重复充值请求只入账一次；`88.00` 元订单完成后支付状态为 `SETTLED`、卖家到账 `88.00`；`66.00` 元订单取消后支付状态为 `REFUNDED`、买家冻结余额恢复为 `0.00`。
- 冒烟测试使用的临时用户、商品、订单及资金数据已从测试库清理。
- `git diff --check` 通过。

### 使用前置
